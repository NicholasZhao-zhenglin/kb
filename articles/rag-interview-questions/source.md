## 使用方式

这份问答用于围绕真实项目组织回答。参考回答描述本次审查见到的代码和证据；没有实施或上线的方案，应明确说“我建议”，不能改写成已完成的项目经验。

## 1. 用两分钟介绍系统

**参考回答：** rag 是锁定前后端子模块的文档问答原型。React 19 页面通过 Axios 调 FastAPI，上传文件后在服务进程同步解析、切块、远程向量化，再 bulk 写 Elasticsearch；聊天对查询做嵌入、全文/向量召回与重排，取引用后流式生成答案和推荐问题。目前不是完整多用户平台：登录/历史接口缺失，上传与新会话的索引命名不一致。审查记录三个提交，并用离线探针验证关键断点。

**追问/误答：** “用了 RAGFlow 目录就是部署了 RAGFlow 服务吗？”不是，默认链调用内嵌解析/NLP 代码，HTTP 适配器未接线。
**依据：** `.gitmodules`、`app_main.py`、`chat_rt.py`、01 模块表。

## 2. 最值得保留的设计是什么？

**参考回答：** 解析、检索、生成与路由有明确的文件级入口，适合建立 gateway 替换外部依赖；子模块提交锁定利于复现；SSE 使用 json.dumps 编码，前端通过 finally 清理 loading。这些是局部保障。我会在保留这些边界的基础上修正契约，不先拆微服务。

**追问/误答：** 模块拆文件不等于网络隔离，也不自动提供事务。需要进一步检查状态由谁持有。
**依据：** `file_parse.py`、`retrieval.py`、`chat.py`、`pages/chat/index.tsx::sendChat`。

## 3. 为什么文件上传成功，聊天却查不到？

**参考回答：** 当前前端上传不传 session_id，后端写 default；聊天主页新建随机 session，检索用它作为索引名，中间没有关联。P02 捕获真实路由实参证明两者不同。另一个独立原因是 F05：bulk 错误列表被丢弃。所以不能只凭页面 success 排查模型效果，应先验证集合身份与数据确实可见。

**追问/误答：** “把相似度阈值调低就行”不能解决命名空间不一致。
**依据：** F02/F05；`api/session.ts::upload/chat`、`execute_insert_process`。

## 4. 会话 ID 能否充当访问控制？

**参考回答：** UUID 降低猜测概率，但服务器仍要判断当前用户是否有权访问这个资料集合。本后端既没有鉴权依赖，又直接用 session_id 拼目录和选索引。P03 仅在临时目录验证父路径越界。最小修复是服务端授权映射、生成存储名和根内路径检查，而不是仅增加随机字符串长度。

**追问/误答：** 前端 AuthGuard 只检查本地 token，不能保护直接 HTTP 调用。
**依据：** F04、`AuthGuard`、`upload_files`、`ESConnection.search`。

## 5. 什么是上传的“成功”？

**参考回答：** 至少要分文件落盘、处理成功、bulk 每项成功、可检索发布四步。当前 ES insert 返回错误列表而上层忽略，P04 表明合成失败仍返回 success；P07 表明非超时异常被清空。建议引入明确结果与 ready 状态，只有完整版本被发布才告知可用于问答。版本发布会增加状态和清理成本，但使失败可恢复。

**追问/误答：** HTTP 200 或 bulk 请求返回，都不能单独证明全部文档正确写入。
**依据：** F05；`es_conn.py::insert`、`file_parse.py::execute_insert_process`。

## 6. 为何用了 async 仍可能阻塞？

**参考回答：** async 路由中直接调用普通解析和同步网络函数，不会自动切换执行器。上传 await read 后和聊天检索阶段都如此。流生成器被 StreamingResponse 迭代是另一层，本轮 Starlette 用线程池适配，不能混为一谈。建议先设资源上限和有界隔离，再根据 CPU、I/O 与恢复需求选择线程、进程或 worker。

**追问/误答：** 多开 worker 不能补齐任务状态，可能复制模型内存；本轮没有容量测量。
**依据：** F06、02 执行上下文、05 第 3 节。

## 7. 混合检索默认链是什么？

**参考回答：** query 转分词文本条件和嵌入向量，ES 构造全文与 knn，再候选重排，最终返回最多五条。page_size=5 不等于只召回五条；当前候选 size 至少 128。embd_mdl=None 也不会跳过远程 embedding，因为旧分支已注释。召回、重排和答案生成应分开评估。

**追问/误答：** 能否证明排序正确？本轮没有标注语料评测；Q01 还需核实真实重排返回身份顺序。
**依据：** `retrieval.py::retrieve_content`、`search_v2.py::search/retrieval`。

## 8. 重排包装为什么可能出错？

**参考回答：** 输入 A、B，适配器可能按得分返回 B、A；包装仅输出 score 数组，调用者继续按 A、B 取值，可能给错对象。P08 用换序假适配器演示了这一前提，但没有安装验证自定义包返回行为，所以我把它列为待确认 Q01。修复方向是 ID 和 score 一起传播，或显式映射回输入顺序。

**追问/误答：** 长度一致只证明数量一致，不证明位置语义一致。
**依据：** `rag/nlp/model.py::rerank_similarity`、`Dealer.rerank_by_model`。

## 9. 内容哈希去重有什么代价？

**参考回答：** 当前 hash(content+session) 合并相同段落，却把文件归属一起覆盖；P05 证明两个文档的 chunk ID 相同而 doc_id 不同。若业务要保留每个来源，应把文档/版本纳入身份；若追求存储去重，则单独维护内容实体的多来源关系。选型取决于引用和删除语义，不只看空间节省。

**追问/误答：** 这里不是“xxhash 随机碰撞”，而是确定相同输入产生相同 ID。
**依据：** F08、`process_item`、ES bulk index 操作。

## 10. SSE 的错误为什么不会自动弹出？

**参考回答：** 流开始后 HTTP 可以一直是 200，后续 error 是数据事件。当前前端只解析 data.content，忽略 event 与 role，P09 看到错误文本进入答案。应设计独立错误和终态状态，保留部分答案，并处理取消/EOF。推荐问题是答案结束后的第二个调用，应能单独失败。

**追问/误答：** 只在 Axios catch 中处理非 2xx，覆盖不了流内业务错误。
**依据：** F10、`chat.get_chat_completion`、`sendChat::parseData`。

## 11. 为什么 Markdown 渲染需要安全边界？

**参考回答：** 文档和模型输出都不是可信 HTML。当前 Marked 输出直接送 dangerouslySetInnerHTML；P10 验证合成事件属性仍存在，但没有执行浏览器攻击。我建议按产品需求禁用原始 HTML或做白名单清洗，并回归表格、代码和引用渲染。

**追问/误答：** Markdown 解析器不是 sanitizer；不能用前端已登录作为内容可信的证明。
**依据：** F09、`components/markdown/index.tsx`。

## 12. 如何证明这次审查可靠？

**参考回答：** 我记录总仓库与两个子模块 SHA，区分深入阅读与结构浏览；对接口缺失、索引不一致、临时路径越界、bulk 错误传播、chunk 身份和解析输入使用真实函数配合 fake 外部边界。60 个 Python 文件语法通过，前端默认安装失败，legacy peer 模式构建成功，lint 为 26 errors/10 warnings。我没有把这些结果包装成完整应用或生产验证。

**追问/误答：** 为什么不直接启动后端跑全套？导入会触及配置、资源和外部 SDK；未隔离的启动可能读取秘密或调用服务。AST 探针牺牲初始化覆盖，换取明确的离线验证边界。
**依据：** 01 覆盖矩阵、03 探针摘要、本地 evidence 脚本。

## 13. 有限时间内优先修什么，怎样回滚？

**参考回答：** 先处理凭据、路径/授权与 HTML 边界，再打通登录/上传/问答契约，然后使写入和流状态可信。修复知识库 ID 与文档版本时用新命名空间或发布指针，验证后切读；旧索引保留可回退，不先删数据。完成正确性后再评估队列、分片与模型质量。

**追问/误答：** 没有负载基线不能给出“扩容后快十倍”；轮换秘密不能通过恢复旧秘密回滚。
**依据：** 04 分阶段路线图及迁移章节。

## 表达边界与模拟练习

可以说“审查并离线复现了某路径”“提出了状态/接口方案”；不能说“已修复生产事故”“做过百万并发”“RAG 精度提升多少”。建议用 10 分钟依次介绍系统、一个 F 项的失败机制、最小修复、失败注入验收和未覆盖范围；这是未执行的学习练习，不是新增实施任务。
