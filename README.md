「收藏」不是内容分类，而是**外部资料的收纳处**，由侧栏「我的收藏」入口承载 ——
所以它不出现在分类树与分类地图里，避免和导航项重复。分类总数也只计前两项。

每篇原文逐字保留，未改写只重排：条目标题独占 `h1`，原文的「部分 / 章 / 小节 / 小点」依次落到 `h2 / h3 / h4 / h5`。

## 功能

- **全文检索**：标题 / 标签 / 正文，结果带上下文片段与高亮。`/` 或 `⌘K` 聚焦，`↑↓` 选，`Enter` 打开
- **章节目录**：左栏由正文标题现生成，滚动跟随高亮；点目录做页内跳转，不触发路由
- **我的收藏**：侧栏入口，列出全库的**外部资料**（论文 / 规范 / 开源项目），卡片只给关键词与一段短摘要，点一下直达原文
- **星标 / 最近阅读**：标记与足迹写在浏览器 `localStorage`，不上传不联网
- **深浅主题 / 4 档字号 / 代码块一键复制**
- **导入导出 JSON**：把外部条目追加进本地，或备份后换设备
- **打印样式**：`⌘P` 直接出干净的 PDF

## 加一篇文章

**一个目录 = 一篇文章。不用改任何代码。**

```bash
mkdir -p articles/my-note
```

`articles/my-note/meta.json`：

```json
{
  "order": 3,
  "id": "my-note",
  "cat": "backend-eng",
  "title": "标题",
  "kicker": "副标题（可省略）",
  "summary": "一两句话的摘要，会显示在首页卡片上",
  "tags": ["标签1", "标签2"]
}
```

`articles/my-note/source.html` —— 普通 HTML，正文包在 `<main>` 里：

```html
<!DOCTYPE html><html><head><meta charset="utf-8"></head><body>
<main>
  <h1>标题</h1>
  <p>正文…</p>
  <h2>第一章</h2>
  <p>…</p>
  <h3>1.1 小节</h3>
  <p>…</p>
</main>
</body></html>
```

然后重建：

```bash
python3 build.py
```

**字段约束**（`build.py` 逐条校验，不合格直接报错退出）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 必须与目录名完全一致，也用作锚点前缀 |
| `order` | ✓ | 排序键，整数，不能重复 |
| `cat` | ✓ | 分类 id，必须在 `categories.json` 里登记过 |
| `title` / `summary` / `tags` | ✓ | 不能为空 |
| `kicker` | | 卡片上的小字副标题 |

**写正文时不用操心的事**

- **标题层级**：照原文写就行，生成器整体降一级（条目自己的标题占 `h1`）。降级顺序写反会让全篇小标题塌成一级，这点由断言焊死。
- **锚点 id**：自动加 `<条目id>--` 前缀，多篇合并也不会撞。
- **表格横滑容器**：写裸 `<table>` 即可，`<div class="tw">` 由生成器自动包（自己包过也不会重复包）。
- **目录**：从真实标题现生成，不需要手写 TOC。

**加分类**：编辑 `categories.json` 后重跑。分类里写 `"nav": true` 表示它**不进分类树**，
改由侧栏对应入口承载（目前只有「收藏」这么用，见下一节）。

## 收藏一份外部资料（书签卡片）

不想在库里存副本、只想留个入口的资料（论文、规范、别人维护的教程），
**目录里只放 `meta.json`，不写 `source.html`**，并加一个 `url` 字段：

```json
{
  "order": 3,
  "id": "dso-paper",
  "cat": "bookmarks",
  "title": "Direct Sparse Odometry (DSO)",
  "kicker": "J. Engel · V. Koltun · D. Cremers —— IEEE TPAMI 2018",
  "summary": "视觉里程计：误差直接定义在像素灰度上（光度误差），对几何与相机运动做一致联合优化；不依赖关键点与描述子，去掉平滑先验因而能实时，并把曝光时间、渐晕、非线性响应一并标定。",
  "tags": ["视觉里程计", "SLAM", "三维重建", "运动恢复结构"],
  "url": "https://jakobengel.github.io/pdf/DSO.pdf"
}
```

渲染成一张**小卡片**：标题 + 作者/出处 + 关键词标签 + 一段短摘要 + 「打开原文 ↗」，
**点击直接在新标签打开 `url`**，不经过知识库路由，库里不留正文副本。
这些卡片集中在侧栏**「我的收藏」**里（跨分类聚合，点一下直达原文）。

| 字段 | 必填 | 说明 |
|---|---|---|
| `url` | ✓ | 必须 `http(s)://` 开头；有此字段即视为外链资料 |
| `cat` | ✓ | 仍要填，但要指向一个标了 `"nav": true` 的分类（如 `bookmarks`），它才不会混进分类树 |
| `summary` | ✓ | **≤100 字**，`build.py` 硬卡，超了直接报错退出并打出实际字数 |
| `tags` | ✓ | 渲染成卡片上的关键词标签；建议直接取原文的关键词表翻成中文 |
| 其余 | | 与普通条目相同；`summary` 与 `tags` 都会并进搜索索引 |

**卡片为什么刻意做小**：它只需要回答「这是什么、要不要点进去」。
论文的细节在原文里，把摘要摊开、把要点列全会让单张卡片涨到 785px —— 实测踩过，
所以现在只留「关键词 + 一段短摘要」，并且用断言把高度上限钉住。

写 `tags` 的取法：**优先抄原文自己的关键词表**（IEEE/TPAMI 的 Index Terms、
期刊页的 Keywords），而不是自己总结 —— 这样换成任何人来维护，结果都一样。
原文没有关键词表的（如多数 CVPR 论文），退而从标题与摘要里取它反复使用的术语，并说明来源。

细节：外链资料**不要**放 `source.html`；它的 `words` / `read` 为 0、不进字数与图表统计；
卡片上的关键词是 `<span>` 不是 `<a>`（整张卡片本身就是 `<a>`，锚点不能套锚点），
但标签仍会进「全部标签」页与搜索索引；
搜索结果的条目也指向 `url`；万一有人手输 `#/a/<外链id>`，会把原文开出去并把当前页收回首页。

**想临时试一篇**：加完目录跑 `python3 build.py`，不满意就删掉目录再跑一次 —— 每次都是全量重建，幂等，不会留下残渣。

## 项目结构

```
.
├── index.html                    ← 交付物：知识库本体（CSS / JS / 内容全内联，约 224 KB）
├── categories.json               ← 分类体系（"nav": true 的分类不进分类树）
├── articles/                     ← 一条内容一个目录
│   ├── <id>/meta.json            ←   元信息（外链资料到此为止）
│   ├── <id>/source.html          ←   正文（含 <main>）；外链资料没有这个文件
│   └── …
├── build.py                      ← 生成器：扫描 articles/ 全量重建（纯标准库）
├── verify.js                     ← 逻辑验证：jsdom 里真跑页面脚本，147 项断言
├── cdp-verify.js                 ← 渲染验证：驱动本机 Chrome，93 项断言
└── shots/                        ← 上面那个脚本输出的截图
```

**为什么是全量重建而不是增量追加**：增量追加要「读已有产物 → 插入 → 写回」，一旦有第二个脚本也这么干，
两边就会互相覆盖。本项目真出过这个问题：重新构建会把追加进来的条目整条冲掉，而且不报错。
全量重建的输入只有 `articles/` + `categories.json`，谁是唯一真相一目了然。

## 验证

```bash
# 1) 逻辑：jsdom 里真跑页面脚本
NODE_PATH=<node_modules 路径> node verify.js

# 2) 渲染：驱动本机 Chrome（走 CDP，零 npm 依赖），并出图到 shots/
node cdp-verify.js
```

两个脚本都是**红绿判据**，失败退出码 1。断言写成「UI 忠实反映数据」的结构性不变量
（如「首页卡片数 = 展示分类数 + 条目数」「目录项数 = 正文标题数」），而不是硬编码某个时期的绝对数字 ——
内容增长时不会产生假失败。

**几何类断言要等滚动停稳**：页面 CSS 有 `scroll-behavior:smooth`，`scrollTop = 0` 是一次动画，
Chromium 的动画时长随滚动距离增长。固定 `sleep()` 会在长页面上提前收工，于是「量卡片坐标」发生在滚动途中，
等鼠标真的落下时卡片已经移走 —— 悬浮断言就这么假失败（症状：`hovered=false atPoint=page`）。
`cdp-verify.js` 里用 `settleScroll()` 等「连续两次采样 `scrollTop` 相同」再量，判据与页面长度解耦。

## 设计取舍

- **单文件而不是多文件**：`file://` 下 `fetch` 本地文件会被浏览器拦，内容必须内联；顺带的好处是归档不会散。
- **目录现生成而不是抄原文**：少一处要同步维护的重复清单，也就没有「两份目录对不上」的问题。
- **目录锚点不走 `#` 路由**：路由占用 `#/...`，页内锚点必须 `preventDefault` 手动 `scrollIntoView`，否则点目录会被当成换页。
- **外链只存卡片、不存副本**：论文 / 规范这类资料抓取与维护成本高，而且原文一更新副本就过时。
  卡片承载「它是什么 + 要不要点进去」，原文留在原处，点一下直达。
  卡片有意做小（关键词 + ≤100 字摘要）：把摘要摊开、要点列全，单张能涨到 785px —— 试过，不要。
- **「收藏」不做成分类，而做成导航入口**：外部资料不按主题归类，做成分类只会和侧栏入口重复
  （同一批内容出现两次）。所以分类里标 `"nav": true`，由「我的收藏」统一承载，分类总数也不计它。
- **「收藏」与「星标」是两回事**：收藏 = 外部资料本身（进「我的收藏」，点开跳原文）；
  星标 = 给库内条目做个记号（文章页右上角，落在现有分类树里）。混在一起会让人以为
  「收藏」里应该出现自己标记过的文章 —— 这正是最初踩过的坑。
- **侧栏分类块里不写分类简介**：那一栏只有 240px 宽，两三行介绍必然被截断成半句话，
  还会把下面的条目列表挤在一起（实测会盖住条目标题）。简介只留给分类页 hero 和首页「分类地图」卡片 ——
  那里版面放得下，能整段读完。**同一段文字放不下的地方就别放**，不是把字号调小硬塞。
- **源文件与产物都在仓库里**：`articles/` 是可读可改的输入，`index.html` 是产物；改完重跑，不需要理解生成器内部。
